# 合同用印核查工具

核查一份合同 PDF 的用印是否**齐全、清晰、完整**，并验证其**签署后未被篡改**。

- 支持 **e签宝 / 法大大 / 契约锁 / WPS** 等平台的电子签章 PDF
- 也支持纸质盖章后扫描的 PDF（见「已知限制」）
- **完全离线**，不上传任何文件到第三方服务

---

## 一、环境准备

需要 **Python 3.8+**（Windows / macOS / Linux 均可）。

```bash
pip install pymupdf pillow numpy
```

**还需要 `openssl`**（用于密码学验签）：

| 系统 | 获取方式 |
|---|---|
| Windows | 装 [Git for Windows](https://git-scm.com/download/win) 即自带；脚本会自动找到 |
| macOS | 系统自带，或 `brew install openssl` |
| Linux | 通常已装，或 `apt install openssl` |

> 找不到 openssl 时脚本**不会崩**，会跳过验签并明确提示，其余检查照常进行。

## 二、怎么用

```bash
python seal_check.py 合同.pdf
```

会生成一个同名目录：

```
《合同名》_sealcheck/
├── 核查报告.md          ← 看这个
├── summary.json         ← 机器可读（加 --json）
└── evidence/
    ├── 骑缝章还原_<签名者>.png       ← 最直观的证据
    └── 完整章_p<页>_<签名者>_<域名>.png
```

常用参数：

```bash
python seal_check.py 合同.pdf -o 输出目录      # 指定输出位置
python seal_check.py 合同.pdf --json           # 额外输出 JSON
python seal_check.py 合同.pdf --dpi 200        # 扫描件提速
python seal_check.py 合同.pdf --openssl /path/to/openssl
```

**退出码**：`0` 无问题 / `1` 发现需关注的问题 / `2` 文件不存在 / `3` 缺依赖。
便于批量脚本判断。

## 三、它做四件事

### 1. 结构探测
读取 PDF 元数据，判定是**电子签章**还是**扫描件**，决定用哪套判据。

### 2. 印章核查
- **完整章**：甲方盖章处、乙方盖章处、声明页等处，逐一列出页码与位置
- **骑缝章**：逐页检查切片是否存在、位置是否一致、是否缺页、是否精确等分
- 生成**无缝还原图**——把各页切片拼回整章，一眼看出是否盖全

### 3. 密码学验签
用 openssl 验证 PKCS#7 数字签名：

- **验签通过** → 被签名数据的摘要与签名值一致 → **签署后一字未改**
- **最后一次签名覆盖到文件末尾** → **签署后没有任何追加内容**（防「签后加页」）
- 同时给出**签名者证书主体**与**签发 CA**，确认签署人身份

### 4. 盖章处对账
统计正文中「（盖章）」要求数，与实际印章数比对，并逐处列出要求位置供人工复核。

## 五、判据说明：为什么不依赖固定宽度

**不同合同、不同平台、甚至同一份文件内部，骑缝切片的宽度都可能不同。** 实测一例：

| 层面 | 12 片的宽度 | 是否一致 |
|---|---|---|
| PDF 几何（pt） | `10.0` × 12 | ✅ 完全均匀 |
| 内嵌图像（px） | `56, 56, 55, 55, …` | ❌ 不一致 |

（`662 ÷ 12` 除不尽，平台把余下 2px 分给了前两片。**这是取整，不是设计不一致。**）

所以工具用的是**宽度无关的判据**：

| 判据 | 内容 | 容忍度 |
|---|---|---|
| 存在性 | 每页边缘有印章墨迹 | 宽度任意 |
| 位置一致性 | 贴边距离、纵向位置跨页一致 | ± 数 pt |
| 连续性 | 相邻页切片在页边方向紧邻或重叠 | **允许缝隙、允许重叠** |
| 完整性 | 起止页之间无缺页 | 硬性 |
| **精确等分** | **`Σ切片宽度 == 完整章宽度`** | 等式，不依赖具体数值 |

> **「无缝拼接」只是电子签章里可遇不可求的强化证据，不是通用前提。**
> 纸质骑缝章是扇形展开后盖章，相邻页印迹本身就会**重叠**，要求严格无缝反而不符合物理实际。

## 六、已知限制

| 限制 | 说明 |
|---|---|
| **证书链信任校验** | 只验证「签名与数据匹配」，**不验证证书是否被 Adobe 信任列表认可**（需 AATL 根证书）。请在 Adobe Acrobat 中打开确认显示**绿色勾** |
| **签署人授权** | 证书只能证明「谁签的」，不能证明「此人有权代表公司签署」。需另行核对授权文件 |
| **扫描件支路未校准** | 无表单域的扫描件缺真实样本调参，结果仅供人工参考 |
| **非等分切法** | 若平台按页厚/缩放切分而非均分，无法拼接还原 |
| **印章备案比对** | 未与公安备案印模做像素级比对，此项通常由签章平台保证 |

**结论用于辅助人工判断，不能完全替代法务审核。**

## 八、常见问题

### clone / pip 失败，提示 `Connection was reset` 或超时

`github.com:443` 在部分网络下不稳定，**但 git 不会自动使用系统代理**（这是个常见误解）。如果本机已有代理，给 git 单独指定：

```bash
# 只对本次操作生效
git -c http.proxy=http://127.0.0.1:7897 clone https://github.com/nonamenohome/contract-seal-check.git

# 或写入全局配置（代理关闭后需 --unset 还原）
git config --global http.proxy  http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897
```

端口按本机代理软件实际设置改（Clash 常见 7897/7890，V2Ray 常见 10809）。

### 提示缺少 PyMuPDF / Pillow / NumPy

```bash
pip install pymupdf pillow numpy
```

### 提示找不到 openssl / 跳过了验签

验签是加分项，其余检查不受影响。装上 openssl 即可：

- Windows：装 [Git for Windows](https://git-scm.com/download/win)，脚本会自动找到
- macOS：`brew install openssl`
- Linux：`apt install openssl`

也可以用 `--openssl /path/to/openssl` 手动指定。

### 扫描件（纸质盖章后扫描）结果不准

扫描件没有可读取的签章几何信息，判定是靠图像检测，**容差参数尚未用真实样本校准**，结果仅供人工参考。详见 SKILL.md 的「支路 B」。

### 中文在 Windows 控制台显示乱码

脚本已内置 `sys.stdout.reconfigure(encoding='utf-8')`。若仍乱码，先执行 `chcp 65001`。
